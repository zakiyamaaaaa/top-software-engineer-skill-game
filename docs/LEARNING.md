# 教材の構成と編集方針

## 学習の進め方

1. 章の目標と大切な用語を確認する。
2. 各テーマの説明を読み、仕組みと使う場面を区別する。
3. コード例を順に読み、値・処理・結果がどう変わるかを追う。
4. 記述練習に理由、予想、コードを書く。回答例は書いた後に開く。
5. 確認問題を解く。迷ったら「教材を読み直す」を使う。
6. 章末課題で複数の考え方を組み合わせる。日をあけて復習する。

選択式の正解数はゲーム内の進行に使います。記述練習は自分で回答例と比較する課題であり、自動採点やコード実行は行いません。入力したメモは最大4000文字まで端末に保存され、設定のJSON書き出しにも含まれます。途中のクエスト画面は保存されません。コード例は使用する言語を表示し、疑似コードはそのまま実行するものとして扱いません。

## オブジェクト指向の4つの考え方

- **カプセル化**: データを勝手に変更されないようにし、操作を通じてルールを守る。
- **抽象化**: 使う側に必要な操作を示し、細かい実装を隠す。
- **継承**: 親の機能を子が引き継ぐ。親として使ったときの約束も守る。
- **多態性**: 同じ操作の呼び出しに対して、対象ごとに異なる処理をする。単にメソッド名を揃えるだけでなく、使う側の期待を守る。

4つは同じ意味ではありません。例えば、口座の不正な残高変更を防ぐのはカプセル化、通知の送り方の詳細を隠すのは抽象化、文書を拡張して報告書を作るのは継承、同じ `send` でメールとSMSを送るのは多態性です。部品を持って組み合わせるコンポジションは継承と区別します。

## データと追加基準

- `curriculum.js`: 章、確認問題、選択肢、回答後の説明。
- `learning.js`: 短い概要と図の対応。
- `lessons-core.js`: 第1〜6章の章目標・用語・章末課題と、30テーマの詳しい教材。
- `lessons-applied.js`: 第7〜13章の35テーマを同じデータ形式で追加。

新しいテーマにも「できるようになること」「仕組みを説明する3節」「コード例と順を追った読み方」「よくある間違い」「理由を書く練習と回答例」を揃えます。説明は用語の言い換えだけで終えず、条件・処理・結果と、その仕組みを選ぶ場面を示します。専門用語は最初に意味を説明し、比喩や略語だけで理解を求めません。セキュリティや障害対応の例では、省略している処理や前提を示します。文章量の検査は内容レビューの代わりにはなりません。
